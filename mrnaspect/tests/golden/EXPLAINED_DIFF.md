# Explained diff log — batch changes vs `pre_batch_qc_result.json`

The pre-batch golden was frozen (Wave 0) from the current buggy code as the "what-changed"
baseline. Every reported-output change the batch makes is logged here, each mapped to its
owning item with a one-line justification (UPDATE_PLAN re-validation step 2). A diff with no
owning entry = an unintended regression → stop and investigate. At Wave 6 this table is the
audit trail; the golden is then re-frozen from the corrected code.

Fixture: `small_aligned.bam` (166 reads, 4 curlcakes), `--mode bam --min-reads 1`, default config.
Comparator: `qcrna/tests/golden_compare.py` (strips provenance/timing/report.path/reason).

**This table and `test_golden.py` are one artifact in two forms.** Every row below has a
counterpart in that file — a scalar diff in `EXPECTED_DIFFS`, or, for diffs too large to
enumerate (per-position arrays, top-N lists, per-construct subtrees), a subtree claim in
`OWNED_PREFIXES`. The test fails on a diff no entry claims (an unintended regression) *and*
on an entry that matches no diff (a stale claim). Rows marked **[array]** are the
`OWNED_PREFIXES` half. Keep the two in sync: a row here without an entry there is
unenforced, and an entry there without a row here is unexplained.
