    Help
    
              
    
                
    Which folder to choose
    
                
    MinKNOW writes each run into a folder of its own, three levels under its data folder (on a Mac, /Library/MinKNOW/data):
    

    /Library/MinKNOW/data/
└── my_experiment/
    └── my_sample/
        └── 20261112_1434_MN12345_FBA12345_1a2b3c4d/    ← Live run
            ├── pod5/                                   ← POD5 files
            └── bam_pass/                               ← BAM files, if MinKNOW basecalled
    
                
    
                  
    Live run
    the run folder: the one that holds pod5/
    
                  
    POD5 files
    a folder that holds .pod5 files
    
                  
    BAM files
    a folder that holds .bam files, aligned or not
    
                
    
                
    Any of these levels will do: mRNAspect finds the folder it reads, says how many files it holds, and lists the runs when there are several. Find MinKNOW runs looks in MinKNOW's data folder for you.
    
              
    
              
    
                
    The Overview
    
                
    
                  
    Reads
    every read so far; mapped reads align to your reference
    
                  
    Read length
    the median; full length is the share of reads that reach the construct's 5' end, from its low to its high bound
    
                  
    Poly(A) tail
    the median and IQR, over the reads with a tail called
    
                  
    Read quality
    the basecaller's mean quality score per read: confidence in the call, not agreement with the reference
    
                  
    Construct share
    each construct's share of the reads
    
                  
    Per-base identity
    per construct, the share of base observations that carry the reference base
    
                  
    Full length by construct
    each construct's full-length share, from its low to its high bound
    
                  
    Sequencing information
    pore occupancy, read end reasons and voltage, from MinKNOW's run files
    
                
    
              
    
              
              
    
                
    What the colours mean
    
                
    Each kind of result keeps one colour: on its Overview card, in its panel and in the report on screen.
    
                
    
                  
    Blue
    length: Read length, Full length by construct
    
                  
    Violet
    Poly(A) tail; where both are drawn, the corrected length is a second violet
    
                  
    Teal
    accuracy: Read quality, Per-base identity
    
                  
    Green
    composition: Construct share, and the mapped reads
    
                  
    Red
    something to check: a run that stopped or failed, an error, a flagged position on a figure
    
                  
    Amber
    a caution, such as ⚠ uncorrected beside a poly(A) tail
    
                
    
                
    Where one figure splits a result into parts (the channel states in Sequencing information, the error types in Per-base identity), the same four colours name the parts, and the key beside the figure says which. Nothing relies on colour alone. The PDF report prints in greys and patterns; only a flagged position keeps its red.
    
              
    
              
    
                
    Where the results go
    
                
    Each run writes one folder inside the output folder.
    
                
    
                  
    report_run_end.pdf
    the report, at the end of the run
    
                  
    report_latest.html
    the newest report, rewritten as the run goes
    
                  
    qc_result.json
    every number, machine-readable
    
                  
    run.log
    what the run did
